# YouTube Music parity

The account on music.youtube.com is the source of truth. A local edit is complete only when the service accepts it. Data changed on the web must be reloaded into the native client. Local preferences and the in-progress playback queue remain device state, matching the web player's behavior.

The initial release implements public catalog browsing, search, audio playback and a local queue. Its local likes and saved collections are not account sync. They must not be silently uploaded when an account is connected.

## Required work

Prepared for signed-in verification: account library categories, song ratings and separate library feedback, playlist create/edit/privacy/delete/add/remove/reorder with occurrence IDs, history removal, and account switching/sign-out. The native controls are wired to service requests and refresh after acknowledgement. Account pages also refresh when the window regains focus; Ctrl R refreshes explicitly. None of this is marked complete until tested with an authenticated account against the web client. The reviewed sign-in flow is available so these checks can proceed.

The Podcasts library category opens saved shows; Episodes opens the service's Saved episodes playlist. Saved shows use the same collection-save state as other saved library collections. These destinations were corrected during the public podcast/API audit, but their authenticated contents and actions remain unverified. Episode detail pages now expose the matching playable header, description, show link and duration label. Show association persists through pagination. Episode requests preserve the issued podcast context, refreshing it after restart or account changes; they do not construct a music-radio queue. Native radio and related-music controls use a bounded worker. Current-song account refresh, lyrics and credits have separate bounded workers, so refreshing account state or opening text cannot cancel radio. Closing a text dialog or changing accounts discards its pending results. Public next/lyrics requests, song credits and two further radio pages have passed live service checks. Radio preserves the server's queue order and repeated occurrences. Continued autoplay keeps recommendations separate from the explicit queue and adds one occurrence when that queue ends. Turning autoplay off drops pending recommendations. Queue arrows preserve the selected occurrence, and Clear stops playback and cancels pending recommendations.

Playlist and search playback retain their page continuation separately from navigation. The queue fetches the next page near its loaded end and keeps duplicates in service order. Repeat-all and recommendations wait for explicit tracks to finish. Requests require the original account snapshot; replacing the queue discards late replies. Request context is not persisted. After restart or an account change, unfinished queues must be reopened to fetch the rest. Local tests cover continuation, empty pages, retries, repeated-token rejection, queue edits and stale replies.

Connected playback now queues remote history reporting after mpv starts the track. Reports require matching full server account identity, the requested video ID, a validated YouTube history destination and HTTP 204 acknowledgement. Missing account proof fails closed. Reports and their replies are bound to the exact selected session. Guest playback keeps local history; connected plays are not copied into that guest history. A public player inspection returned a valid tracking destination without submitting history. Actual history persistence on a signed-in account remains unverified.

Settings has saved playback-speed, Low/Normal/High audio quality and video height limits from 144p through 2160p, defaulting to 720p. Quality changes preserve position, pause state, queue and the same-recording history marker. Audio formats follow the service's quality classes, with bitrate fallbacks when those labels are absent. High selects the best stream available for the song and membership. Video selectors preserve the audio choice and reject above-limit or audio-only fallbacks.

The app now embeds one libmpv core with an optional native EGL video view on Wayland and X11. Fullscreen has a button, F and double-click controls; Escape exits it. Audio/Video selection preserves playback state. An exact service-issued Song/Video pair can change the selected recording, with a new playback/history ID and fresh account metadata. Pairs stay in memory under the current account and apply only to their own members. Fixtures cover both directions, duplicate queue occurrences, malformed and ambiguous pairs, and recording-specific account state. No probed public guest response has supplied a live counterpart pair, so real-service counterpart switching remains unverified.

The app owns its MPRIS service. Desktop Next and Previous traverse the application queue and retain paused or stopped state; Stop retains the selected track for Play. Seek requests are bound to the current load. Metadata survives a quality reload, and frequent position samples update a shared clock without waking the D-Bus worker. Local tests cover commands, metadata, timing and validated property changes.

The October 23 review fixed five state-handling issues: page refresh and playlist-picker requests cancelled each other; Pause during radio loading restarted the previous queue; pause confirmation erased active buffering; synchronous mpv requests accepted unrelated replies; and events buffered after those replies waited for more socket traffic. Page and picker requests now retain separate generations and loading state, with visible picker errors and retry. Radio retains pause intent, buffering keeps the desktop clock frozen, and each synchronous mpv request accepts only its own reply. Buffered events are processed even while mpv is otherwise silent. Focused regression tests cover request isolation, buffering and both IPC failures; the radio branch also passed static review. Live paused-radio interaction remains unverified.
