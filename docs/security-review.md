# Account security reviews

## 2026-10-27

A bounded readiness review found that ordinary quit could still detach persistence or edits after the connection indicator cleared. Shutdown now drains the existing account worker for every exit. A synthetic persistence test verifies that finishing waits for an accepted save without clearing the current session.

Connection no longer captures the first signed-in channel automatically. The user selects a Google or brand account in the dedicated browser, then confirms it in native Settings. Failed capture or verification leaves that browser open for an explicit retry. Cancel connection preserves the previous connection and its saved keyring item. Existing stable-identity checks remain enforced. Confirmation and cancellation tests use synthetic operations, without a Google account.

Playlist creation now includes an initial song in the create request. Acknowledged library changes update visible page and row metadata before a refresh, and focus refresh runs even with a dialog or earlier page read pending. Artwork navigation drops unstarted old loads; failed images can retry after a cooldown. Horizontal artwork shelves render their viewport rather than every card. These changes received a separate read-only regression review with no concrete new defect found. They do not extend the sealed October 23 scan.

Validation passed 129 ordinary tests, all 22 guest/offline integration tests, formatting, strict all-target Clippy and a release build. No real Google credentials were used. Native release snapshots confirmed Settings and Home rendering, and targeted Escape dismissed Settings. Native Ctrl Q during pending connection exited the app and its dedicated Chromium process and removed the owned temporary profile. Pointer scrolling and confirmation/cancellation clicks remained unverified because both background and foreground input left the window unchanged; desktop capture failed with an X11 GetImage Match error.

Real account compatibility remains unverified. In particular, no authenticated account-menu fixture establishes that the endpoint supplies the stable identity required for activation. Public upstream WEB_REMIX fixtures for other endpoints omit it. This is a proof gap, not evidence that the check can safely be removed. First sign-in, saved-session restoration, brand switching, authenticated playback and cross-client mutations still require a real-account check.

## 2026-10-23

A whole-repository source review covered the 74 tracked paths at `4fb9970`. It reported one low-severity CWE-459 issue: normal quit during pending sign-in could detach the account worker and leave its temporary browser profile behind. A native test with no credentials reproduced the retained profile. The review did not establish a remote or cross-user disclosure, and its source findings do not certify real account compatibility.

Shutdown now cancels and joins pending account work. Restore lookup uses the existing owned keyring child guard with cancellation and a deadline; private RAM output files avoid pipe-capacity deadlocks. Ordinary quit preserves saved credentials. Failed sign-out keeps a retry control and prevents reconnecting until cleanup succeeds. Repeated removal succeeds when the keyring item is already absent, including after rollback of a revoked save. A synthetic Secret Service store/read/remove/remove test verifies this without accessing the application's credential entry.

A controlled installed-mpv check also showed that a stop acknowledgement and `idle-active` can precede extractor termination. Credential replacement now consumes an event-queue marker after stopping, waits for any started file to end, resets extractor options and closes the old descriptors before acknowledging completion. The marker catches a `start-file` event that has not reached the client yet. Sign-out waits for that acknowledgement and keyring removal. Synthetic local extractors exercise replacement, clearing, fatal exit and shutdown without network access or real credentials. A regression reproduced premature cleanup before the marker fix. Another installed-libmpv check passed 100 immediate Play/clear cycles without waiting for extractor readiness.

Account activation now requires matching stable primary or brand identity from the account-menu response. Synthetic tests reject missing and conflicting identity; compatibility with real Google account responses still requires signed-in verification.

Native release verification repeated the original quit-during-sign-in trigger with an empty dedicated profile. The app and Chromium exited, and the temporary profile was removed. No real Google credentials were used. This proves normal cancellation cleanup, not forced-exit cleanup or authenticated compatibility.

Final validation passed all 121 ordinary tests, all 22 optional guest/offline integration tests, formatting, strict all-target Clippy and the release build. The integration checks include isolated Chromium transport, synthetic keyring entries and extractor credentials, public catalog requests, and guest playback through the null audio output. The user chose to finish with real Google sign-in, authenticated playback and cross-client account checks unverified.

## 2026-10-17 and subsequent checkpoints

The source review covered every changed source file between e9cfcdf and 5899fb5. It found no reportable vulnerability in that gated build. This is a bounded review, not a guarantee that the application has no vulnerabilities.

The subsequent hardening and playback checkpoint is 460b17f. The account gate is still off in that revision.

Subsequent hardening binds queued edits, persistence, catalog and song-detail jobs to a verified session. Failed verification preserves the previous session. Connection completion must match the active, uncancelled operation in both the worker and UI. Persistence starts only after UI acceptance and playback credential allocation; revoked writes are removed. Closing during pending sign-out drains account cleanup, with bounded keyring child processes. Sign-out clears navigation history, overlays and in-memory action tokens. Account feedback tokens, occurrence IDs and rating snapshots are excluded from device-state serialization.

Playback now carries the selected account index and full primary/brand identity through sealed RAM. The embedded extractor requires matching server identity before returning formats, rejects logout and conflicting player responses, and uses a single HTTP handler that refuses redirects before forwarding authorization. A missing plugin or different yt-dlp version fails closed. External plugins and user configuration are disabled. Playback uses an acknowledged stop before replacing or closing its private RAM files. Raw extractor diagnostics cannot reach user-facing playback errors. These later changes received a separate bounded source review; they are not covered by the earlier sealed scan.

Validation passed:

- 35 ordinary tests, including session binding, cancelled publication, failed verification, disabled imports, revoked storage, cleanup after UI closure, request redaction, RAM file permissions/lifetimes and account metadata parsing.
- Nine offline extractor cases against installed yt-dlp 2026.08.19, covering multiple Google/brand accounts, returned identity, explicit logout, missing proof, redirects, private context, plugin failure and unsupported versions.
- A live isolated Chromium transport check with no debugging TCP port or inherited extensions.
- Live public guest mpv playback, pause and seek. Invented credentials no longer have a live streaming test because authenticated playback must reject an unconfirmed account rather than fall back to guest playback.
- A synthetic Secret Service store/read/remove round trip under unique test attributes. No existing credential entry was accessed.

No real Google account was used by the checks above. Authenticated compatibility and cross-client mutations remain unverified. Sign-in and saved-session loading are now available for controlled live verification; cookie imports are unsupported. A private runtime lock prevents concurrent app processes from racing shared account state. Its exclusivity, release and symlink refusal have a focused test.

The search and autoplay checkpoint passes 47 ordinary tests and strict all-target Clippy. Suggestions reject replies from a previous query, generation or exact account session. Radio continuation carries its original account identity and rejects another session before making a request. These checks supplement the earlier review; they do not extend the sealed security scan to newer commits. The user deferred sign-in, and no authenticated cross-client check has run.

The history and playback-speed checkpoint passes 53 ordinary tests and strict all-target Clippy, including five history contracts and a validated speed boundary. A separate source review found that the first history implementation checked the video but lacked server account proof. A regression reproduced that gap before it was fixed. Reporting now requires the full selected primary/brand identity and rejects conflicting account hints before accepting the tracking URL. The bounded recheck found no remaining concrete defect in that fix. Public player inspection validated a history destination without submitting it; live guest playback passed pause, seek and speed changes. Actual signed-in history remains unverified.

The credits and scoped-search checkpoint passes 56 ordinary tests and strict all-target Clippy. Song text uses immutable account snapshots on a separate bounded worker; account changes and dialog closure invalidate pending results. Account search rejects unsupported combinations, explicit logout, missing scope tabs and explicitly unselected results. Public credits, search categories and pagination passed live checks. Native guest checks covered suggestions, category search, Back navigation, credits, persisted speed, queue reordering/clearing and autoplay settings. These are feature and boundary checks, not an extension of the sealed scan or a substitute for authenticated verification.

The audio-quality checkpoint passes 60 ordinary tests and strict all-target Clippy. Its bounded source review found two pause-confirmation races, both corrected and covered by focused regressions. Stream replacements retain pause intent until mpv confirms the latest command, including no-op assignments and intervening external controls. New playback IDs isolate old load failures and end events. Changing quality keeps the existing history-reporting marker and does not replace the queue, radio or account session. An offline selector check and live muted guest playback passed, including a Low-quality reload paused at 30 seconds and subsequent external unpause. Authenticated quality selection and real account history remain unverified.

One native High-quality load failed. Public diagnosis found intermittent HTTP 403 failures affecting Normal too, while repeated High loads at the same paused position succeeded. The native failure itself remained unclassified because extractor diagnostics are kept private. The app now makes one fresh extraction attempt after a track-specific failure before Started, preserving playback and history state. Global/process failures and failures after Started are reported immediately. A focused state test and bounded source recheck verified the retry budget, stale IDs and account isolation. mpv's public error event does not distinguish HTTP 403, 404 or 500, so this recovery applies to any track-specific startup failure.

The final native check passed High playback, paused High/Normal changes at 22 seconds, resumption, unchanged queue selection and quality preference restoration after restarting the app. The preceding build also passed a playing switch to Low. These checks used a muted guest fixture; they did not access a real Google account or verify signed-in history.

The discovery checkpoint passes 62 ordinary tests and strict all-target Clippy. Navigation targets keep their validated browse IDs and bounded encoded parameters in the existing fixed-endpoint, session-bound request path. Malformed links are rejected, and navigation items have no collection-save controls. Focused parsing tests, live public destinations and native category/Refresh/Back checks passed. This adds no credential path and does not extend the earlier sealed scan or establish authenticated parity.

The browse-filter checkpoint passes 65 ordinary tests and strict all-target Clippy. Home reset actions and chart country choices are parsed from service state. The client extracts validated browse targets instead of executing service commands, and only Charts accepts a form value, restricted to one uppercase two-letter country token. Country changes require a service-confirmed matching selection. The picker accepts events only from its active entity, and account changes drop it and its subscription. A bounded source review found no concrete issue in this change. Public reads passed Home selection/reset and Canada, United Kingdom and Global charts. Signed-in parser compatibility and cross-client behavior remain unverified.

Native checks caught modal key handling swallowing printable input. The fix consumes only handled navigation keys, and the app's modal guard runs before search/refresh shortcuts. Native country search, selection, empty results, Escape and Refresh/Back passed. A separate local fixture verified playlist title/description typing, Tab and submission without an account. These checks establish input behavior, not successful remote playlist edits.

The pagination checkpoint passes 69 ordinary tests and strict all-target Clippy. Each continuation owns its original visitor header and exact account snapshot; a changed account is rejected before preparing a request. Visitor headers are validated and marked sensitive, and continuation Debug output is redacted. No visitor state is shared globally or persisted. Home and section-list continuation pages use their own page token instead of a nested shelf token. Live public Home checks returned two further pages; public search categories, suggestions and song pagination still pass. Authenticated pagination remains unverified.

The episode-details checkpoint passes 77 ordinary tests and strict all-target Clippy. Episode header IDs and issued parameters are validated; missing transient parameters refresh through a matching episode read under the same Catalog session. Parameters are excluded from serialization and Debug output and cleared on account changes. Public descriptions remain plain text. A bounded source review found a queue-end loading defect, fixed by sharing music-autoplay eligibility across queue advance, waits and recommendation loading; delayed episode classification also stops a cancelled wait. No other concrete defect was found within this scope. A live guest check covered episode/show reads, 100 continued show rows, restored context and a matching podcast queue. Account playback, progress and saves remain unverified.

The chapter checkpoint passes 79 ordinary tests, strict all-target Clippy and a release build. Chapter targets come only from matching-video watch endpoints in the episode's scoped description. The client uses validated numeric seconds, never executes description links, and renders titles as plain text. The source review found a paused stream-replacement edge case, corrected by reusing the existing reload path and its history marker. Public chapter parsing and muted native start/paused-seek checks passed; account progress remains unverified.

The seek checkpoint passes 85 ordinary tests, strict all-target Clippy and a release build. Seeks carry a playback ID and revision through the existing actor. A replacement stream invalidates outstanding work, and credential changes still stop before releasing RAM files without waiting for seeks. Completion uses a fresh post-restart position observer; retired observer IDs cannot overwrite it. Source review found and closed superseded-success/latest-failure fallback and duplicate-query failure cases. A tagged seekability check rejects inputs that cannot provide the completion event contract, including cache-only seeking. Fourteen focused player tests, an actual private synthetic-audio check, public streaming and native paused seek/quality/resume checks passed. No credentials or authenticated playback were used.

The native-video checkpoint adds a single in-process libmpv core and a renderer that owns its Wayland or X11 child resources. A bounded source review found a required Xlib threading initialization before GPUI/libmpv startup, now enforced. Desktop startup caught a CLI-only mpv script alias. Desktop controls subsequently moved into the app's MPRIS service, and the player no longer loads the external plugin. Renderer hooks register once during construction. Failure latches, first-swap readiness, modal detachment and synchronous close/quit teardown keep borrowed window handles within their lifetime. The renderer joins before core destruction; credential files outlive that core. Reviewed extractor and account boundaries still apply. This review does not cover unknown codec or driver vulnerabilities, and a blocked in-process driver can stall shutdown.

Song/Video pairs come only from validated service wrappers. Review found stale queue matching, delayed-mode application, loss of reverse-switch metadata and failed-enqueue playback ownership defects. Membership checks, transient account-cleared pair retention, exact-current response binding and retiring the old load before enqueueing corrected them. Inactive autoplay results keep their existing advance path, and async metadata cannot reopen the video view after navigation. A bounded recheck found no remaining concrete issue in these changes. No real account or authenticated sync was tested.

Production Wayland checks passed Stop/Play through renderer detachment and reattachment. The GPUI Wayland event source releases its prepared-read guard before dispatching UI callbacks, so the proposed wait cycle through that guard was not established. Uninstrumented 30-second samples on both display backends recorded zero dropped frames. An earlier XWayland rendering stall remains unresolved; these samples do not establish driver-failure recovery or audible A/V synchronization.

## Dependency maintenance

On October 23, 687 locked packages were checked against RustSec advisory database commit `f7b2f6bc663452200bbe639ebb75e0c762b3422b`. Version requirements were matched using Rust's semver implementation, excluding withdrawn advisories. The check found [RUSTSEC-2026-0381](https://rustsec.org/advisories/RUSTSEC-2026-0381.html) in `webpki-roots 1.0.9` and [RUSTSEC-2026-0382](https://rustsec.org/advisories/RUSTSEC-2026-0382.html) in `rustls-webpki 0.103.15`. These concern acceptance of distrusted certificate intermediates. The lockfile now uses patched versions `1.0.10` and `0.103.16`. A repeat check found no matching active vulnerability or unsoundness advisory. Six transitive dependencies still match unmaintained advisories, with no patched versions listed:

- [zvariant 5.15.0, RUSTSEC-2026-0370](https://rustsec.org/advisories/RUSTSEC-2026-0370.html)
- [zvariant_derive 5.15.0, RUSTSEC-2026-0372](https://rustsec.org/advisories/RUSTSEC-2026-0372.html)
- [zbus_names 4.3.4, RUSTSEC-2026-0371](https://rustsec.org/advisories/RUSTSEC-2026-0371.html)
- [ttf-parser 0.25.1, RUSTSEC-2026-0192](https://rustsec.org/advisories/RUSTSEC-2026-0192.html)
- [rustybuzz 0.20.1, RUSTSEC-2026-0206](https://rustsec.org/advisories/RUSTSEC-2026-0206.html)
- [paste 1.0.15, RUSTSEC-2024-0436](https://rustsec.org/advisories/RUSTSEC-2024-0436.html)

These enter through GPUI's Linux, font, SVG and image dependencies. Their maintenance status needs upstream migration; it is not evidence of a particular exploit. The check excludes the browser, mpv, yt-dlp, OS packages and unpublished vulnerabilities.

Browser-cookie authentication gives the application broader YouTube authority than a narrow OAuth grant. An unlocked desktop keyring or compromised user session remains outside the application's isolation guarantees. See [the account design and limits](account-security.md).
